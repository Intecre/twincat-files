File Handling user guide

Save a PLC structure to a JSON file and read it back at start-up. Write and read CSV files a field at a time, write text files a line at a time, and check that a file is there. Every block works in the background over several PLC cycles, so a file operation never holds up your task.

1What the library does

The library is Intecre.File, a TwinCAT 3 library. Its namespace is Intecre_File.

BlockWhat it does
T_StructPersistenceKeeps one structure in a JSON file. It reads the file into the structure at start-up, creates the file if it is missing, and can write the structure back on its own after it changes (section 5).
T_StructToJsonFileWriterWrites any structure to a file as JSON (section 6).
T_StructFromJsonFileReaderReads a JSON file into a structure of the same type (section 6).
T_CsvFileWriterBuilds a CSV file field by field and row by row, then writes or appends it (section 7).
T_CsvFileReaderReads a CSV file and hands you one field at a time, with its row and column (section 7).
T_TxtFileWriterBuilds a text file from strings and lines, then writes or appends it (section 8).
T_CheckFileExistsSays whether a file is there (section 9).

The JSON blocks use Beckhoff's Tc3_JsonXml, so any structure works, with no code per type. The member names in the file are the member names in the structure:

{"Name":"Batch 7","Speed":2.5,"Count":7,"Enabled":true}

2How every block works

File access in TwinCAT takes several PLC cycles. The blocks never wait for it. You start an operation with a method call. Then you call the instance once every cycle, which moves the operation on, and watch its status until it has finished.

Five rules hold for every block:

  1. Call the instance every cycle, for example recipeReader(); at the top of your program, whether or not an operation is running. Nothing moves without it.
  2. Start with a method: ReadFromFile(), WriteToFile(), GetFile() or Check(). A start is ignored while the instance is busy.
  3. Wait until Busy is FALSE, then read Error. On the JSON reader, Done can be TRUE as well as Error: the file was read but could not be used.
  4. One operation at a time per instance. Use a second instance to work on a second file at the same time.
  5. Paths are on the PLC, not on the engineering PC: C:\Data\Recipe.json is on the target's disk. On the user-mode runtime the PLC is the PC itself.

3Before you start

Install the library

You need TwinCAT 3.1.4026 or later. The library needs Intecre.Utilities 4.1 or later, for its logging and base class. The Beckhoff libraries it uses (Tc2_Standard, Tc2_System, Tc2_Utilities and Tc3_JsonXml) come with every 4026 XAE.

  • From a release. Download Intecre_File.library from the GitHub releases and install it with PLC > Library Repository > Install. Install Intecre.Utilities the same way, from the twincat-utils releases.
  • As a TcPkg package. The release also carries Intecre.File.1.3.1.nupkg, which declares its dependencies. Put it in a folder, add that folder as a source with tcpkg source add -n local -s <folder>, and run tcpkg install Intecre.File. TcPkg then wants the Intecre.Utilities package too: put its .nupkg from the twincat-utils release in the same folder.

Then, in your PLC project, choose References > Add library > Intecre.File (Intecre Ltd).

Turn the log on

The blocks report problems through the Intecre.Utilities logger, which is off until you set a level. Reference Intecre.Utilities as well, and set the level once at start-up:

Intecre_Utilities.LogConfig.LogLevel := Intecre_Utilities.E_LogSeverity.Warning;

Messages from the JSON blocks start with the instance path, for example MAIN.recipeReader: . They are listed in section 11.

Know the sizes

Two sizes are library parameters. You can change them for your project on the Parameters tab of the Intecre.File reference:

ParameterDefaultWhat it limits
JsonParams.JSON_DOC_SIZE10000The characters of JSON one reader or writer can hold, so the largest structure it can save or load. Allow the structure's size plus at least 20 % for the names and punctuation.
Param.TXT_FILE_MAX_STRING_LENGTH300The string type TxtFileString that T_TxtFileWriter.Write takes.

Other sizes are fixed: a path is a T_MaxString (255 characters), except in ST_PersistenceOptions (80), and a CSV field is a STRING (80). See section 10.

4Quick start: a recipe file

This keeps a recipe in C:\Data\Recipe.json. At start-up it loads the file, or creates it from the recipe's initial values. After that it saves the recipe on request, and also on its own after the recipe has changed.

  1. Declare the structure as a type of its own. The block finds it by the type's name. 
    TYPE ST_Recipe :
STRUCT
  Name : STRING;
  Speed : LREAL := 1.0;
  Count : DINT;
  Enabled : BOOL;
END_STRUCT
END_TYPE
  2. Declare the recipe, its options and the block. 
    PROGRAM PRG_Recipe
VAR
  recipe : ST_Recipe;
  recipeOptions : ST_PersistenceOptions := (
    NameOfStructureType := 'ST_Recipe',   // the type, not the variable
    FilePath := 'C:\Data\Recipe.json'
  );
  recipeFile : T_StructPersistence;
  saveRequested : BOOL;
END_VAR
  3. Call it every cycle. Give it the recipe's address and size each time, so an online change that moves the recipe cannot leave it pointing at the old place. 
    recipeOptions.AddressOfStruct := ADR(recipe);
recipeOptions.SizeOfStruct := SIZEOF(recipe);
recipeFile(Options := recipeOptions);

IF saveRequested AND recipeFile.WriteToFile() THEN
  saveRequested := FALSE;
END_IF
    WriteToFile() returns FALSE while a read or write is running. Keep asking, as here, until it returns TRUE.
  4. Run it. The first time, there is no file: WriteSuccess and FileCreated rise and the file holds the initial values. After a restart, ReadSuccess rises and the recipe holds what the file held. 
    {"Name":"","Speed":1.0,"Count":0,"Enabled":false}
Leave the recipe alone just after the read ReadSuccess rises a few cycles before the block has finished with the file. A change in those cycles can be taken as what the file holds, and then it is not saved on its own (section 12). Wait until WriteToFile() would be accepted, or about half a second, before you change the structure from code.

5Keeping a structure in a file: T_StructPersistence

The block takes its settings from the Options input. It reads the path, the type name, and whether to create the file, once, on its first call. The other options it reads every cycle.

OptionDefaultMeaning
AddressOfStruct, SizeOfStruct–ADR(recipe) and SIZEOF(recipe).
NameOfStructureType–The name of the structure's type, such as 'ST_Recipe'. Not the variable's name.
FilePath–The full path on the PLC. At most 80 characters (section 12).
CreateFileIfDoesntExistTRUEWhen the first read finds no file, write the structure as it is now.
AutoWriteOnDifferenceTRUESave the structure on its own after it changes.
AutoWriteCheckTimeT#2MHow often to look for a change. The block compares a CRC of the structure with the CRC of what it last read or wrote.
AutoWriteDebounceTimeT#30SAfter a change is seen, how long the structure must stay the same before it is written. An operator who edits several values in turn gets one write, not several.
Output or methodMeaning
ReadSuccessThe last read filled the structure from the file.
WriteSuccessThe last write saved the structure.
FileCreatedThe file was missing and has been written for the first time.
ReadFromFile() : BOOLRead the file into the structure again. FALSE, and nothing happens, while a read or write is running.
WriteToFile() : BOOLSave the structure now. FALSE, and nothing happens, while a read or write is running.

With the defaults, a change is on disk between 30 s and about 2 min 30 s after the last edit. Call WriteToFile() when it must be on disk sooner, for example when an operator presses Save.

A file from another version of the structure If you add a member to the type, an old file has no value for it. If you rename one, the file's value is not found. Check after the first read that the structure holds what you expect, and write it back to bring the file up to date.

6JSON files

Use the reader and writer directly when you want to choose the moment of every read and write, keep several files for one type, or read a file that a PC wrote.

Writing

VAR
  recipeWriter : T_StructToJsonFileWriter;
END_VAR

recipeWriter();

IF save THEN
  save := FALSE;
  recipeWriter.SetFileParams(
    FilePath := 'C:\Data\Recipe.json',
    StructureName := 'ST_Recipe',
    PointerToStructure := ADR(recipe),
    SizeOfStructure := SIZEOF(recipe)
  );
  recipeWriter.WriteToFile();
END_IF

Reading

VAR
  recipeReader : T_StructFromJsonFileReader;
END_VAR

recipeReader();

IF load THEN
  load := FALSE;
  recipeReader.SetFileParams(
    FilePath := 'C:\Data\Recipe.json',
    StructureName := 'ST_Recipe',
    PointerToStructure := ADR(recipe),
    SizeOfStructure := SIZEOF(recipe)
  );
  recipeReader.ReadFromFile();
END_IF

Then wait for Busy to fall. The writer has Done or Error. On the reader, Error decides: when it is FALSE and Done is TRUE, the structure holds the file. FileExists says whether the file was there.

MemberReaderWriter
SetFileParams(...)The path, the type's name, and the structure's address and size. Call it before the first read or write, and again to change file or structure.
ReadFromFile() / WriteToFile()Starts a read. The structure changes only when the whole file has been read and parsed.Turns the structure into JSON at once, then starts the write. Changes after the call are not in the file.
Busy, Done, ErrorAs in section 2. Error stays TRUE until Reset.
FileExistsFALSE when the last read found no file.–
Reset()Clears Error. Both blocks refuse to start while Error is TRUE. On the reader, call Reset() and ReadFromFile() one after the other (section 12).

What the reader refuses

  • A file longer than JSON_DOC_SIZE. The reader sets Error, logs the file's length and the limit, and leaves the structure as it was. Before 1.3.1 it copied the whole file and overwrote the memory after its buffer.
  • A file that is not valid JSON for the type. Error is set. The structure may hold some of the file's values, so do not use it.
  • A missing file. Error is set and FileExists is FALSE.

The file the writer makes

One line of compact JSON, with no line end and, from 1.3.1, no NUL byte at the end. Numbers are written as numbers, a BOOL as true or false, and a string in quotes. The writer replaces the file if it exists.

7CSV files

Writing: T_CsvFileWriter

VAR
  logWriter : T_CsvFileWriter;
END_VAR

logWriter();

IF logNow AND NOT logWriter.Busy THEN
  logNow := FALSE;
  logWriter.SetFileParams(FilePath := 'C:\Data\Log.csv', Separator := ASCI_COMMA);
  logWriter.SetFileOpenMode(Append := TRUE);
  logWriter.ClearBuffer();
  logWriter.AddStringField(sFieldString := 'Batch 7');
  logWriter.AddStringField(sFieldString := LREAL_TO_STRING(speed));
  logWriter.AddStringField(sFieldString := DINT_TO_STRING(count));
  logWriter.WriteToFile();   // ends the row, then writes
END_IF
Batch 7,2.5,7
MemberMeaning
SetFileParams(FilePath, Separator)The path, and ASCI_COMMA or ASCI_SEMI_COLON. Any other separator gives a semicolon.
SetFileOpenMode(Append)TRUE adds to the end of the file. FALSE, the default, replaces the file.
ClearBuffer()Empties the buffer and sets Row and Column to 0. Call it before building the next file. It does nothing while Busy.
AddStringField(sFieldString)Adds a field, with a separator before it unless it is the first on the row.
NewLine()Ends the row with CR LF.
WriteToFile()Ends the row, then writes the buffer. So a file always ends with a line end, and you do not call NewLine() after the last field.
Row, ColumnWhere the next field goes, counted from 0.
Busy, Done, Error, ErrorIdAs in section 2. ErrorId is the ADS error from the file system, such as 1804 for a path that is not there.
Build the next file only when the last write has finished While Busy is TRUE, the buffer refuses new fields and they are lost without a message. Check NOT Busy before ClearBuffer(), as above.
The separator is shared SetFileParams sets Tc2_Utilities.DEFAULT_CSV_FIELD_SEP, which is one global for the whole PLC. Every CSV reader and writer uses the separator of the last SetFileParams call. Use one separator throughout, or set it just before each file.

Reading: T_CsvFileReader

csvReader();

CASE step OF

  0:

    csvReader.SetFileParams(FilePath := 'C:\Data\Points.csv', Separator := ASCI_COMMA);
    csvReader.GetFile();
    step := 10;

  10:

    IF csvReader.Busy THEN
      RETURN;
    END_IF

    IF csvReader.Error THEN
      step := 100;   // look at csvReader.ErrorId and csvReader.FileExists
      RETURN;

    END_IF

    csvReader.NextField();
    WHILE NOT csvReader.Eof DO
      points[csvReader.Row, csvReader.Column] := csvReader.Field;
      csvReader.NextField();
    END_WHILE
    step := 20;

END_CASE

GetFile() reads the whole file into memory. Then each NextField() moves on by one field, at once, with no waiting, so a loop can take the whole file in one cycle. For a large file, stop the loop after a number of fields and carry on in the next cycle, so the task keeps its cycle time.

MemberMeaning
SetFileParams(FilePath, Separator)As for the writer, and the separator is the same shared global.
GetFile()Starts reading the file and goes back to the first field.
Busy, Error, ErrorId, FileExistsAs in section 2. Check Error before parsing: after a failed read, ReadyForParsing can still be TRUE (section 12).
ReadyForParsingThe file has been read.
NextField()Moves to the next field. The first call gives the first field.
Field, Row, ColumnThe current field, and where it is, counted from 0.
EofTRUE once NextField() has gone past the last field. Field then holds nothing useful.

8Text files: T_TxtFileWriter

textWriter();

IF report AND NOT textWriter.Busy THEN
  report := FALSE;
  textWriter.SetFileParams(FilePath := 'C:\Data\Shift.txt');
  textWriter.ClearBuffer();
  textWriter.WriteLine('Shift report');
  textWriter.Write('Parts made: ');
  textWriter.WriteLine(DINT_TO_STRING(partsMade));
  textWriter.WriteToFile();
END_IF
Shift report
Parts made: 412
MemberMeaning
SetFileParams(FilePath)The full path on the PLC.
SetFileOpenMode(Append)TRUE adds to the end of the file. FALSE, the default, replaces the file.
ClearBuffer()Empties the buffer and sets Row to 0. It does nothing while Busy.
Write(Entry)Adds text to the current line. At most 255 characters a call (section 12).
WriteLine(Entry)Adds text and ends the line with CR LF.
NewLine()Ends the line.
WriteToFile()Writes the buffer. Unlike the CSV writer, it adds no line end of its own.
RowThe number of lines ended so far.
Busy, Done, Error, ErrorIdAs for the CSV writer. A folder that does not exist gives Error: the writer does not create folders.

9Checking that a file exists: T_CheckFileExists

fileCheck();

IF checkNow THEN
  checkNow := FALSE;
  fileCheck.Check(Path := 'C:\Data\Recipe.json');
END_IF

IF NOT fileCheck.Busy THEN
  recipeFileFound := fileCheck.FileExists;
END_IF

The block opens the file for reading, and closes it again if that worked. FileExists is FALSE while Busy is TRUE. A file that is there but cannot be opened, because it is locked or protected, reads as not there.

10Sizes and memory

WhatSize
JSON a reader or writer can holdJsonParams.JSON_DOC_SIZE characters, 10 000 by default. Each reader and each writer has its own buffer of that size, and T_StructPersistence has one of each, so about 20 kB of PLC memory per persistence block with the default.
A path255 characters (T_MaxString). 80 in ST_PersistenceOptions.FilePath.
A CSV field, written or read80 characters (STRING).
Text a T_TxtFileWriter.Write call adds255 characters.
A file being readHeld whole in router memory while the block works on it, and freed at the next read.
A file being builtGrows in router memory as you add to it, and is freed by ClearBuffer().

To see what a structure needs, write it once and look at the file's size. To raise JSON_DOC_SIZE, open the Intecre.File reference in your project, choose the Parameters tab, change the value and build. Large files and many blocks use router memory: raise it in the TwinCAT system settings if you see Out of memory messages.

11Messages and what to do

Turn the log on first (section 3). Messages go to the TwinCAT log, which shows in XAE's Error List and output window. A message from a JSON block starts with the instance path:

MAIN.recipeReader: JSON file not read: it is 12480 bytes, more than JsonParams.JSON_DOC_SIZE (10000). Increase JSON_DOC_SIZE in the Intecre.File library parameters.

What you seeWhat to do

12Limits and known issues

The TestRunner project in this repository has a TcUnit suite for every block, and each test states the intended behaviour. The issues below are the tests that fail today. They are listed so that you can work around them until they are fixed.

IssueWork-aroundTest
T_StructPersistence: ReadSuccess rises a few cycles before the read has finished. Until it has, WriteToFile() returns FALSE, and a change to the structure can be taken as what the file holds, so it is not written on its own.Keep calling WriteToFile() until it returns TRUE. Leave the structure alone for about half a second after ReadSuccess.Test_WriteToFileSavesTheCurrentStruct, Test_AutoWritesAfterTheStructChanges
T_StructPersistence: after a read fails, for example because the file was missing and CreateFileIfDoesntExist is FALSE, ReadFromFile() fails again even when the file is now there.Leave CreateFileIfDoesntExist TRUE, or use the reader directly.Test_ReadsAgainAfterAFailedRead
ST_PersistenceOptions.FilePath holds 80 characters. A longer path is cut short.Keep the path to 80 characters.Test_CreatesAFileWithAPathLongerThan80Characters
T_StructFromJsonFileReader: after a file error, Reset() on its own does not hold. The next call of the instance sets Error again from the old read.Call Reset() and ReadFromFile() one after the other, with no call of the instance in between. The code says this works; no test covers it yet.Test_ReaderReadsAgainAfterAnErrorAndReset
T_CsvFileReader: after a failed read, ReadyForParsing is TRUE.Check Error first.Test_MissingFileGivesAnError
T_CsvFileReader.Field holds 80 characters. A longer field is cut short.Keep fields to 80 characters.Test_KeepsFieldsLongerThan80Characters
T_CsvFileWriter does not quote a field. A field holding the separator splits into two.Remove or replace the separator in the text first.Test_QuotesAFieldContainingTheSeparator

T_TxtFileWriter.Write keeps 255 characters of each call, although TxtFileString holds 300.Split longer text over several Write calls.Test_KeepsLinesLongerThan255Characters

Other limits, by design:

  • One operation at a time per instance, and starts are ignored while it is busy.
  • The CSV separator is one global for the whole PLC, and only comma or semicolon.
  • Files are read whole into memory, so a very large file needs router memory of its size.
  • The writers replace or append whole files. They do not create folders, and do not write safely: a power cut during a write can leave the file short. Keep a copy of files you cannot lose.
  • Checked on one setup. TwinCAT 3.1 build 4026 on the user-mode runtime, 10 November 2026: 35 TcUnit tests, of which 24 pass and 11 fail, the 11 being the issues above. Not yet checked: a real-time target, and a changed JSON_DOC_SIZE set through the library reference.
