File Handling user guide

Save a PLC structure to a JSON file and read it back at start-up. Write and read CSV files a field at a time, write text files a line at a time, and check that a file is there. Every block works in the background over several PLC cycles, so a file operation never holds up your task.

1What the library does

The library is Intecre.File, a TwinCAT 3 library. Reference it as the placeholder Intecre.File; its namespace is Intecre_File.

PartWhat it gives you
T_StructPersistenceOne structure kept in a JSON file. It reads the file into the structure at start-up, creates the file if it is missing, and writes the structure back on its own after it changes.
T_StructToJsonFileWriterAny structure written to a file as JSON.
T_StructFromJsonFileReaderA JSON file read into a structure of the same type.
T_CsvFileWriterA CSV file built field by field and row by row, then written or appended.
T_CsvFileReaderA CSV file handed back one field at a time, with its row and column.
T_TxtFileWriterA text file built from strings and lines, then written or appended.
T_CheckFileExistsWhether a file is there.

The JSON blocks use Beckhoff's Tc3_JsonXml, so any structure works with no code per type. The member names in the file are the member names in the structure:

{"Name":"Batch 7","Speed":2.5,"Count":7,"Enabled":true}
Where to look for more

2How every block works

File access in TwinCAT takes several PLC cycles. The blocks never wait for it. You start an operation with a method call. Then you call the instance once every cycle, which moves the operation on, and watch its status until it has finished.

Five rules hold for every block:

  1. Call the instance every cycle, for example recipeReader(); at the top of your program, whether or not an operation is running. Nothing moves without it.
  2. Start with a method: ReadFromFile(), WriteToFile(), GetFile() or Check(). A start is ignored while the instance is busy.
  3. Wait until Busy is FALSE, then read Error. On the JSON reader, Done can be TRUE as well as Error: the file was read but could not be used.
  4. One operation at a time per instance. Use a second instance to work on a second file at the same time.
  5. Paths are on the PLC, not on the engineering PC: C:\Data\Recipe.json is on the target's disk. On the user-mode runtime the PLC is the PC itself.

3Quick start

You need TwinCAT 3.1.4026 or later. This keeps a recipe in C:\Data\Recipe.json: it loads the file at start-up, or creates it from the recipe's initial values, and then saves the recipe on request and on its own after it changes.

  1. Install the libraries. Download Intecre_File.library from the twincat-files releases and IntecreUtilities.library (4.1 or later) from the twincat-utils releases. Install both with PLC > Library Repository > Install. The Beckhoff libraries they use (Tc2_Standard, Tc2_System, Tc2_Utilities and Tc3_JsonXml) come with every 4026 XAE.
  2. Reference them. In your PLC project, choose References > Add library and add Intecre.File (Intecre Ltd) and Intecre.Utilities (Intecre Ltd).
  3. Turn the log on. The blocks report problems through the Intecre.Utilities logger, which is off until you set a level. Set it once at start-up: 
    Intecre_Utilities.LogConfig.LogLevel := Intecre_Utilities.E_LogSeverity.Warning;
    Without it every refusal is silent (section 10).
  4. Declare the structure as a type of its own. The block finds it by the type's name. 
    TYPE ST_Recipe :
STRUCT
  Name : STRING;
  Speed : LREAL := 1.0;
  Count : DINT;
  Enabled : BOOL;
END_STRUCT
END_TYPE
  5. Declare the recipe, its options and the block, and call the block every cycle. NameOfStructureType is the type's name, not the variable's. Give the block the recipe's address and size every cycle, so an online change that moves the recipe cannot leave it pointing at the old place. 
    PROGRAM PRG_Recipe
VAR
  recipe : ST_Recipe;
  recipeOptions : ST_PersistenceOptions := (
    NameOfStructureType := 'ST_Recipe',
    FilePath := 'C:\Data\Recipe.json'
  );
  recipeFile : T_StructPersistence;
  saveRequested : BOOL;
END_VAR

recipeOptions.AddressOfStruct := ADR(recipe);
recipeOptions.SizeOfStruct := SIZEOF(recipe);
recipeFile(Options := recipeOptions);

IF saveRequested AND recipeFile.WriteToFile() THEN
  saveRequested := FALSE;
END_IF
    WriteToFile() returns FALSE while a read or write is running, so the code keeps asking until it returns TRUE.
  6. Run it. The first time, there is no file: WriteSuccess and FileCreated rise, and the file holds the initial values. After a restart, ReadSuccess rises and the recipe holds what the file held. 
    {"Name":"","Speed":1.0,"Count":0,"Enabled":false}
The library is also a TcPkg package Each release carries Intecre.File.1.3.1.nupkg, which declares Intecre.Utilities and the Beckhoff library packages as dependencies. With the Intecre TcPkg feed configured, tcpkg install Intecre.File installs everything. Otherwise put both Intecre packages in a folder, add it as a source with tcpkg source add -n local -s <folder>, and install from there.

4Keeping a structure in a file

T_StructPersistence takes its settings from the Options input. It reads the path, the type name and whether to create the file once, on its first call. The other options it reads every cycle.

OptionDefaultMeaning
AddressOfStruct
SizeOfStruct		–ADR(recipe) and SIZEOF(recipe).
NameOfStructureType–The name of the structure's type, such as 'ST_Recipe'. Not the variable's name.
FilePath–The full path on the PLC. At most 80 characters (section 11).
CreateFileIfDoesntExistTRUEWhen the first read finds no file, write the structure as it is now.
AutoWriteOnDifferenceTRUESave the structure on its own after it changes.
AutoWriteCheckTimeT#2MHow often to look for a change. The block compares a CRC of the structure with the CRC of what it last read or wrote.
AutoWriteDebounceTimeT#30SAfter a change is seen, how long the structure must stay the same before it is written. An operator who edits several values in turn gets one write, not several.
Output or methodMeaning
ReadSuccessThe last read filled the structure from the file.
WriteSuccessThe last write saved the structure.
FileCreatedThe file was missing and has been written for the first time.
ReadFromFile() : BOOLRead the file into the structure again. FALSE, and nothing happens, while a read or write is running.
WriteToFile() : BOOLSave the structure now. FALSE, and nothing happens, while a read or write is running.

With the defaults, a change reaches the disk between 30 s and about 2 min 30 s after the last edit. Call WriteToFile() when it must be on disk sooner, for example when an operator presses Save.

A change made just as the first read finishes can stay unsaved ReadSuccess rises a few cycles before the block has finished with the file. A change in those cycles is taken as what the file holds, so it is not written on its own. Leave the structure alone for about half a second after ReadSuccess, or save it with WriteToFile() (section 11).
An old file has no value for a new member If you add a member to the type, a file written before has no value for it. If you rename one, the file's value is not found. Check after the first read that the structure holds what you expect, and write it back to bring the file up to date.

5JSON files

Use the reader and writer directly to choose the moment of every read and write, to keep several files for one type, or to read a file that a PC wrote.

Writing

VAR
  recipeWriter : T_StructToJsonFileWriter;
  save : BOOL;
END_VAR

recipeWriter();

IF save THEN
  save := FALSE;
  recipeWriter.SetFileParams(
    FilePath := 'C:\Data\Recipe.json',
    StructureName := 'ST_Recipe',
    PointerToStructure := ADR(recipe),
    SizeOfStructure := SIZEOF(recipe)
  );
  recipeWriter.WriteToFile();
END_IF

Reading

VAR
  recipeReader : T_StructFromJsonFileReader;
  load : BOOL;
END_VAR

recipeReader();

IF load THEN
  load := FALSE;
  recipeReader.SetFileParams(
    FilePath := 'C:\Data\Recipe.json',
    StructureName := 'ST_Recipe',
    PointerToStructure := ADR(recipe),
    SizeOfStructure := SIZEOF(recipe)
  );
  recipeReader.ReadFromFile();
END_IF

Then wait for Busy to fall. The writer has Done or Error. On the reader, Error decides: when it is FALSE and Done is TRUE, the structure holds the file. FileExists says whether the file was there.

MemberReaderWriter
SetFileParams(...)The path, the type's name, and the structure's address and size. Call it before the first read or write, and again to change file or structure.
ReadFromFile(), WriteToFile()Starts a read. The structure changes only when the whole file has been read and parsed.Turns the structure into JSON at once, then starts the write. Changes after the call are not in the file.
Busy, Done, ErrorAs in section 2. Error stays TRUE until Reset().
FileExistsFALSE when the last read found no file.–
Reset()Clears Error. Both blocks refuse to start while Error is TRUE.
On the reader, Reset() on its own does not hold after a file error The next call of the instance sets Error again from the failed read. Call Reset() and ReadFromFile() one after the other, with no call of the instance in between (section 11).

What the reader refuses

  • A file longer than JsonParams.JSON_DOC_SIZE. The reader sets Error, logs the file's length and the limit, and leaves the structure as it was.
  • A file that is not valid JSON for the type. Error is set. The structure may hold some of the file's values, so do not use it.
  • A missing file. Error is set and FileExists is FALSE.

The file the writer makes

One line of compact JSON, with no line end and no NUL byte at the end. Numbers are written as numbers, a BOOL as true or false, and a string in quotes. The writer replaces the file if it exists.

When the JSON does not fit

Each reader and each writer holds the JSON in a buffer of JsonParams.JSON_DOC_SIZE characters, 10 000 by default. Allow the structure's size plus at least 20 % for the names and punctuation; to see what a structure needs, write it once and look at the file's size. JSON_DOC_SIZE is a library parameter: to raise it, open the Intecre.File reference in your project, choose the Parameters tab, change the value and build.

6CSV files

Writing a CSV file

T_CsvFileWriter builds the file in memory, then writes or appends it in one go.

VAR
  logWriter : T_CsvFileWriter;
  logNow : BOOL;
  speed : LREAL;
  count : DINT;
END_VAR

logWriter();

IF logNow AND NOT logWriter.Busy THEN
  logNow := FALSE;
  logWriter.SetFileParams(FilePath := 'C:\Data\Log.csv', Separator := ASCI_COMMA);
  logWriter.SetFileOpenMode(Append := TRUE);
  logWriter.ClearBuffer();
  logWriter.AddStringField(sFieldString := 'Batch 7');
  logWriter.AddStringField(sFieldString := LREAL_TO_STRING(speed));
  logWriter.AddStringField(sFieldString := DINT_TO_STRING(count));
  logWriter.WriteToFile();
END_IF

With speed at 2.5 and count at 7, each run adds a row:

Batch 7,2.5,7
MemberMeaning
SetFileParams(FilePath, Separator)The path, and ASCI_COMMA or ASCI_SEMI_COLON. Any other separator gives a semicolon.
SetFileOpenMode(Append)TRUE adds to the end of the file. FALSE, the default, replaces the file.
ClearBuffer()Empties the buffer and sets Row and Column to 0. Call it before building the next file. It does nothing while Busy.
AddStringField(sFieldString)Adds a field, with a separator before it unless it is the first on the row.
NewLine()Ends the row with CR LF.
WriteToFile()Ends the row, then writes the buffer. So a file always ends with a line end, and you do not call NewLine() after the last field.
Row, ColumnWhere the next field goes, counted from 0.
Busy, Done, Error, ErrorIdAs in section 2. ErrorId is the ADS error from the file system, such as 1804 for a path that is not there.
Fields added while a write is running are lost While Busy is TRUE, the buffer refuses new fields without a message. Check NOT Busy before ClearBuffer() and the fields, as in the example.
The separator is one global for the whole PLC SetFileParams sets Tc2_Utilities.DEFAULT_CSV_FIELD_SEP. Every CSV reader and writer uses the separator of the last SetFileParams call. Use one separator throughout, or set it just before each file.

Reading a CSV file

T_CsvFileReader reads the whole file into memory. Then each NextField() moves on by one field at once, with no waiting, so a loop can take the whole file in one cycle.

VAR
  pointsReader : T_CsvFileReader;
  points : ARRAY[0..99, 0..9] OF STRING;
  step : INT;
END_VAR

pointsReader();

CASE step OF

  0:

    pointsReader.SetFileParams(FilePath := 'C:\Data\Points.csv', Separator := ASCI_COMMA);
    pointsReader.GetFile();
    step := 10;

  10:

    IF pointsReader.Busy THEN
      RETURN;
    END_IF

    IF pointsReader.Error THEN
      step := 100;
      RETURN;

    END_IF

    pointsReader.NextField();
    WHILE NOT pointsReader.Eof DO
      points[pointsReader.Row, pointsReader.Column] := pointsReader.Field;
      pointsReader.NextField();
    END_WHILE
    step := 20;

  20:
    ;

  100:
    ;

ELSE
  step := 100;

END_CASE

Step 100 is the error state: ErrorId and FileExists say what went wrong. A real program also checks Row and Column against the array's bounds. For a large file, stop the loop after a number of fields and carry on in the next cycle, so the task keeps its cycle time.

MemberMeaning
SetFileParams(FilePath, Separator)As for the writer, and the separator is the same global.
GetFile()Starts reading the file and goes back to the first field.
Busy, Error, ErrorId, FileExistsAs in section 2.
ReadyForParsingThe file has been read. After a failed read it can still be TRUE, so check Error first.
NextField()Moves to the next field. The first call gives the first field.
Field, Row, ColumnThe current field, at most 80 characters, and where it is, counted from 0.
EofTRUE once NextField() has gone past the last field. Field then holds nothing useful.

7Text files

T_TxtFileWriter builds a text file in memory from strings and lines, then writes or appends it.

VAR
  shiftReportWriter : T_TxtFileWriter;
  writeReport : BOOL;
  partsMade : DINT;
END_VAR

shiftReportWriter();

IF writeReport AND NOT shiftReportWriter.Busy THEN
  writeReport := FALSE;
  shiftReportWriter.SetFileParams(FilePath := 'C:\Data\Shift.txt');
  shiftReportWriter.ClearBuffer();
  shiftReportWriter.WriteLine('Shift report');
  shiftReportWriter.Write('Parts made: ');
  shiftReportWriter.WriteLine(DINT_TO_STRING(partsMade));
  shiftReportWriter.WriteToFile();
END_IF
Shift report
Parts made: 412
MemberMeaning
SetFileParams(FilePath)The full path on the PLC.
SetFileOpenMode(Append)TRUE adds to the end of the file. FALSE, the default, replaces the file.
ClearBuffer()Empties the buffer and sets Row to 0. It does nothing while Busy.
Write(Entry)Adds text to the current line. At most 255 characters a call (section 11).
WriteLine(Entry)Adds text and ends the line with CR LF.
NewLine()Ends the line.
WriteToFile()Writes the buffer. Unlike the CSV writer, it adds no line end of its own.
RowThe number of lines ended so far.
Busy, Done, Error, ErrorIdAs for the CSV writer. A folder that does not exist gives Error: the writer does not create folders.

As with the CSV writer, text added while Busy is TRUE is lost without a message.

8Checking that a file exists

T_CheckFileExists opens the file for reading, and closes it again if that worked.

VAR
  recipeFileCheck : T_CheckFileExists;
  checkNow : BOOL;
  recipeFileFound : BOOL;
END_VAR

recipeFileCheck();

IF checkNow THEN
  checkNow := FALSE;
  recipeFileCheck.Check(Path := 'C:\Data\Recipe.json');
END_IF

IF NOT recipeFileCheck.Busy THEN
  recipeFileFound := recipeFileCheck.FileExists;
END_IF
MemberMeaning
Check(Path)Starts the check. The path can be 255 characters long.
BusyThe check is running.
FileExistsThe file is there. FALSE while Busy is TRUE.
A file that cannot be opened reads as not there A file that is locked by another program, or protected, gives FileExists FALSE. Do not create a new file over it on that basis alone.

9Upgrading

From 1.2.0 to 1.3.1.0

There are no interface changes. Install 1.3.1.0, and references to Intecre.File that resolve to the newest version pick it up at the next build.

ChangeWhat to check
T_StructFromJsonFileReader refuses a file longer than JSON_DOC_SIZE, with Error and a log message. Before, it copied the whole file and overwrote its own settings and the memory after its buffer.A project whose files are close to the limit now gets Error where it used to get odd behaviour. Check Error after every read, and raise JSON_DOC_SIZE if the log shows the message (section 5).
T_StructToJsonFileWriter no longer writes a NUL byte at the end of the file.Files are one byte shorter. PC code that stripped the 0 byte still works; code that compared file sizes or checksums sees a change. The reader reads files from either version.
Built and tested on TwinCAT 3.1.4026, and Tc3_JsonXml is no longer pinned to 3.3.4.0.On an older XAE, test before you upgrade, or stay on 1.2.0.

10Messages and what to do

Turn the log on first (section 3, step 3). Messages go to the TwinCAT log, which shows in XAE's Error List and output window. A message from a JSON block starts with the instance path:

MAIN.recipeReader: JSON file not read: it is 12480 bytes, more than JsonParams.JSON_DOC_SIZE (10000). Increase JSON_DOC_SIZE in the Intecre.File library parameters.

From the JSON blocks and T_StructPersistence

JSON file not read: it is N bytes, more than JsonParams.JSON_DOC_SIZE (M). Increase JSON_DOC_SIZE in the Intecre.File library parameters.The file is too long for the reader, and the structure is unchanged. Raise JSON_DOC_SIZE (section 5), or check that the path names the file you meant.
Error while adding to write buffer. Try increasing JsonDoc size using JsonParams in library, or TC mailbox size.The structure's JSON is longer than JSON_DOC_SIZE, and nothing was written. Raise the parameter.
Error while creating json file from structure. Check argument for SetFileParamsThe type name is wrong, or is the variable's name instead of the type's, or the address or size is wrong. Check StructureName or NameOfStructureType.
Cannot read from file while block is in an error state. Reset first

11Limits

Sizes

Other limits

  • One operation at a time per instance. Starts are ignored while it is busy.
  • The CSV separator is one global for the whole PLC, and only a comma or a semicolon.
  • Files live in router memory while the blocks work on them. A file being read is held whole until the next read; a file being built grows until ClearBuffer(). A very large file needs router memory of its size.
  • The writers replace or append whole files. They do not create folders, and do not write safely: a power cut during a write can leave the file short. Keep a copy of a file you cannot lose.
